# Threat model

The protected assets are uploaded originals, extracted supplier and pricing evidence, tenant membership, case decisions, and credentials. The application trusts the operator, deployment host and database administrators. Members, external MCP clients, PDFs and model output are separate trust boundaries.

| Boundary | Control in this MVP | Remaining exposure |
| --- | --- | --- |
| Browser to REST | Argon2id passwords, hashed opaque sessions, strict HttpOnly cookies, Secure cookies on public origins, exact Origin on mutations, database-backed sign-in throttling, CSP and text-only rendering | No SSO, MFA, password recovery or email verification. Configure ingress rate limits for public access. IP throttling relies on correctly configured trusted proxies. |
| Tenant to database and objects | Membership provides the workspace ID. Application queries scope records by workspace and case. Composite foreign keys constrain writes. Objects use generated UUID paths in a private bucket. The original checksum is verified before parsing and download. | Isolation depends on the application query layer. There is no database RLS, per-tenant encryption key or separate storage account. |
| Upload to extraction worker | 5 MiB raw body cap, PDF signature check, bounded page and text counts, time-limited PDF and OCR subprocesses, bounded raster dimensions, originals served as attachments | Parser and OCR processes share the application OS identity. The PDF parser has Linux memory and CPU limits. Native helpers have individual timeouts. Accept uploads from authorized collaborators during a pilot. |
| Source review and corrections | Page previews require case access and return a PNG. Corrections require the reviewer role, record the reason and actor, and advance the case revision in the same transaction. Extracted values and original bytes are retained. | A reviewer can enter an incorrect value. The source and correction history allow the team to inspect the change. Database operators can alter the history. |
| Remote HTTP to MCP | TLS on public origins, exact Host and Origin validation, bearer credential per case, 1-hour expiry, hashed tokens, explicit revocation, stateless transport | This controlled-client endpoint uses manually issued bearer credentials. It does not implement MCP OAuth discovery or dynamic client registration. A stolen token can read evidence and propose within its scope until revoked or expired. |
| Host to model | Explicit operator enablement and per-run user consent, fixed HF Router URL, bounded turns and calls, a read-only allowlist, validation against returned finding IDs | The router and selected provider receive the question and selected source quotes. IDs can be validated but free-text commentary can still mislead. Check provider terms and data handling before enabling. |
| Proposal to decision | A different reviewer signs in, server checks tenant and role, lock serializes decision and evidence revision changes, audit in the same transaction | Database operators can alter the audit table. Decisions are internal dispositions. The system has no payment authority or ERP integration. |
| Restarts and dependencies | Job leases and attempt fencing, versioned SQL migrations, locked dependencies, CI audit, non-root container | No alerting, automated backup/restore drills or object lifecycle reconciliation. A failed DB commit after an upload can leave an unreferenced object. Clean up by comparing keys with database records after confirming jobs are idle. |

Object keys and database rows are retained until the operator handles retention. Filenames and evidence quotes may contain sensitive information. Access events record IDs, actions and timestamps. They intentionally omit credentials, prompt content, model responses and raw files. Application audit records include successful evidence reads and tool calls reaching the handlers. Malformed requests rejected before a handler may appear only in edge logs.

The local `stdio` command relies on operator access to the database. Keep it on trusted machines and use the HTTP token flow for team clients. For a pilot, limit invited accounts, document data retention and backups, and keep Hugging Face disabled until external processing is approved.
